# Packaging

Everything Apex builds as an RPM, and how CI builds it. The image compose never runs
`cargo` or `rpmbuild` itself: each package is built by its own workflow, published as a
content-addressed OCI artifact, and fed to the single depsolve of the compose through a
local repository (`createrepo_c`, priority 1; see
[ARCHITECTURE section 3](../docs/ARCHITECTURE.md#3-delivery-model-bootc-on-the-ostree-backend)
and [ADR 0013](../docs/adr/0013-build-pipeline.md)).

| Piece | Builds | Workflow | Output |
|---|---|---|---|
| `../Makefile`, `apex.spec` | the `apex` RPM: `apexctl`, `apex-updated`, `apex-boot-assess` and their data files | `rpms.yml` | `ghcr.io/sekirokenjii/apex-rpms:<key>` |
| `licenses.py` | the `License:` tag of `apex.spec`, from `cargo metadata` | `rust.yml` and `rpms.yml` (check) | pass/fail |
| `libfprint/` | Fedora's libfprint SRPM plus the ELAN 04f3:0c6e patches | `libfprint.yml` | `ghcr.io/sekirokenjii/apex-libfprint:<key>`, or "degraded" |
| `kernel/` | a thin fork of Fedora's kernel (COPR) | none: **M2, deferred** ([ADR 0005](../docs/adr/0005-kernel-fedora-fork.md)) | none |

## The apex RPM

One `make install` target defines the installed layout for both development and the
RPM, and it is exactly the table in section 2 of
[docs/specs/M1-IMPLEMENTATION.md](../docs/specs/M1-IMPLEMENTATION.md). The spec only
calls the Makefile:

| Spec section | Runs |
|---|---|
| `%build` | `cargo fetch --locked`, then `make build AUDITABLE=yes`: `cargo auditable build --release --locked --bin apexctl --bin apex-updated --bin apex-boot-assess` with Fedora's `RUSTFLAGS` |
| `%install` | `make install DESTDIR=%{buildroot} PREFIX=/usr` (never builds) |
| `%check` | `make check-data`: `xmllint` on the D-Bus and polkit XML, `systemd-analyze verify` on the units and the emergency/rescue drop-ins in a staged root; desktop and metainfo validation once the M2 app exists |

Decisions recorded in the spec:

- **Network build, not vendored.** Crates come from crates.io during `%build`, pinned by
  the committed `Cargo.lock`. That works because CI runs `rpmbuild` in a
  `registry.fedoraproject.org/fedora:45` container with network access. Vendoring is needed only if
  the build moves to COPR or mock.
- **cargo-auditable** is required (`%bcond auditable 1`) but not packaged by Fedora, so
  CI installs the release binary pinned in `.github/scripts/install-tool.sh` (version
  and SHA-256, bumped together by Renovate) before `rpmbuild`, and only while the spec
  builds with it. `--without auditable` exists for local builds.
- **No debuginfo sub-packages** by default (`%bcond debuginfo 0`): the RPM only feeds
  the compose and is never served to a debugger; symbols stay in the binaries, and
  `--with debuginfo` rebuilds the same commit with DWARF when a core dump needs it.
- **Release from git:** `0.<commit date>.git<12-hex commit>.fc45`, set by `make rpm`
  through the `commitdate` and `shortcommit` macros (`0.0.gitunknown` without them).
- **Scriptlets:** `%systemd_post`/`%systemd_preun` for all four units. On upgrade only the
  timer restarts: `apex-updated` is D-Bus activated (a restart could kill a running bootc
  operation), and the two oneshots would run again. No `%tmpfiles_create`: in an image
  compose `/var` is not the target's, so `/var/lib/apex` comes from `apex.conf` at boot.
- **License:** `GPL-3.0-or-later AND` the licenses of every crate linked into the three
  binaries. `python3 packaging/licenses.py` computes it (normal dependencies only, no
  build, dev or proc-macro crates, x86_64 Linux); `--check packaging/apex.spec` fails
  when a dependency change makes the tag stale. `rust.yml` runs the check on every
  change, and `rpms.sh build` runs it before `make rpm`, so a stale tag is never
  packaged. After a dependency change, run `python3 packaging/licenses.py` and paste
  its `License:` line (and the breakdown comment above it) into the spec. The per-crate
  breakdown ships as `LICENSE.dependencies`, generated by Fedora's `%cargo_license`.
- **Runtime requirements** beyond bootc and ostree: `grub2-tools-minimal`
  (`grub2-editenv`), plus `/usr/bin/unshare` and `/usr/bin/mount` (util-linux-core),
  because `/boot` is read-only on bootc systems and every grubenv write runs in a
  private mount namespace with `/boot` remounted read-write (contract section 5).

### In CI (`rpms.yml`)

`.github/scripts/rpms.sh build OUTDIR` does the whole build, as root in
`registry.fedoraproject.org/fedora:45@sha256:…` with the repository checked out. Every
dnf5 call names the image compose's repositories (`REPOS` below: `--repo=fedora
--repo=updates`, plus `--repo=updates-testing` limited by `includepkgs` to the
allowlisted builds while `GA_REACHED=0`), never the container's defaults, which enable
all of updates-testing before GA:

```bash
dnf5 -y install $REPOS dnf5-plugins rpm-build make git-core findutils tar xz curl python3
dnf5 -y builddep $REPOS packaging/apex.spec
# only while apex.spec has `%bcond auditable 1`: the pinned release, SHA-256 checked
.github/scripts/install-tool.sh cargo-auditable /usr/local/bin
python3 packaging/licenses.py --check packaging/apex.spec
make rpm        # git runs with safe.directory set for this command only
# -> target/rpm/RPMS/x86_64/apex-0.1.0-0.<date>.git<hash>.fc45.x86_64.rpm, SRPMS/…
```

`make rpm` refuses a checkout without commits, refuses a spec `Version` that differs
from the workspace version in `Cargo.toml`, and warns that uncommitted changes are not
in the package (it runs `git archive HEAD`).

The cache key (`rpms.sh key`, the tag of `ghcr.io/sekirokenjii/apex-rpms`) covers
everything that changes the RPM: `git ls-tree -r HEAD` of `crates/`,
`packaging/apex.spec`, the root `Makefile`, `Cargo.toml`, `Cargo.lock`, and `LICENSE`
and `README.md` (packaged as `%license` and `%doc`), plus the `rust` NEVRA those
repositories resolve, the cargo-auditable pin while the spec builds with it, and the
recipe (the repository options and `rpms.sh` itself), so a change to how the RPM is
built never reuses RPMs built the old way. A cache hit is used only after
`oci-artifact.sh lookup` has verified that `rpms.yml` on `main` attested that digest.

### Locally

```bash
make build                      # cargo auditable when installed, plain cargo otherwise
make install DESTDIR=/tmp/apex  # the exact layout of the RPM, without root
make check-data                 # validators that are installed; the rest are skipped
make rpm RPMBUILD_FLAGS='--without auditable'   # in the Fedora 45 builder VM
```

## libfprint

See [libfprint/README.md](libfprint/README.md). In short: `build.sh key` gives the cache
key (Fedora's libfprint NVR plus a hash of the enabled patches); on a miss, `build.sh`
downloads the same SRPM the compose would install, verifies its signature against the
pinned Fedora 45 key, applies `series`, builds `libfprint-…-1.fc45.apex1`, and runs the
elan replay tests. Exit 3 means degraded: the image ships Fedora's stock libfprint with
`io.github.sekirokenjii.apex.degraded=fingerprint` and an issue is opened, so OS updates
never wait for this package.

## Kernel (M2)

See [kernel/README.md](kernel/README.md): a `kernel-local` config overlay, a spec header
(`buildid .1.apex`, Zen 3 `kcflags`), the not-yet-upstream ALC294 quirk (disabled until
measured) and a `make_srpm` recipe that pins Fedora's dist-git commit and verifies every
lookaside source. Nothing uses it until the ADR 0005 gates hold.
